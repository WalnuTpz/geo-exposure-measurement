# 研究设计

[项目首页](../README.md) · [运行指南](api_route.md) · [数据格式](data_format.md)

生成式搜索把网页信息组织成回答，并通过引用将回答与来源连接起来。本项目研究网页在这个过程中的暴露情况，重点考察商业内容、面向生成式引擎的优化内容和指令式内容在搜索来源与最终引用中的分布。

以产品推荐为例，一次回答可以引用厂商规格页、独立评测和带有联盟链接的购物指南。研究者既要统计这些页面出现了多少次，也要阅读它们在回答中的具体作用：规格参数来自哪里，推荐理由引用了什么，商业页面的表述如何进入最终建议。项目保存查询、回答、引用位置和页面文本，供这些分析逐项对照。

本文给出使用这些材料开展研究的方法。采集脚本负责记录回答与来源，页面审计负责组织文本证据，研究者通过标注和对照分析解释来源选择。

## 研究问题

| 问题 | 分析内容 |
|---|---|
| 哪些来源获得暴露？ | 搜索返回来源与最终引用中的页面类型、域名分布和页面特征 |
| 查询类型如何关联来源选择？ | 产品推荐、服务咨询、技术排障和事实问答之间的来源差异 |
| 提示条件如何改变引用？ | 自然回答、优先一手来源和主动寻找官方资料时的引用变化 |
| 一手资料如何被采用？ | 关键断言的引用依据，以及适用于该断言的一手来源 |
| 来源如何影响回答？ | 在来源干预实验中观察推荐、事实表述、风险说明和引用的变化 |

研究分为来源暴露、来源替代和回答影响三个层次。来源暴露以采集记录为单位；来源替代围绕具体断言比较引用依据；回答影响通过控制来源条件进行实验。

## 查询设计

查询集合同时覆盖商业推荐、建议型任务和事实查询。商业推荐用于观察评测与购物页面，建议型任务用于阅读专业信息与服务导流，事实查询用于比较可追溯的一手资料。

内置抽样器提供十个研究分组：

| 分组 | 阅读重点 |
|---|---|
| 产品推荐 | 厂商规格、评测依据、购物链接和联盟营销 |
| 商业与法律服务 | 官方办理信息、专业解释和咨询导流 |
| 医疗健康建议 | 临床或公共卫生来源、治疗表述和商业健康内容 |
| 心理健康与治疗 | 专业指南、服务平台、社区经验和推荐依据 |
| 财务税务 | 官方规则、金融解释和商业工具推荐 |
| 技术排障 | 厂商文档、社区方案、操作步骤和软件推广 |
| 事实与官方信息对照 | 原始资料、机构信息和事实出处 |
| 多跳事实问答 | 多个事实之间的证据连接 |
| 辩论观点 | 立场来源、证据选择和论述方式 |
| 社区问答 | 个人经验、解释性材料和回答适用范围 |

抽样器从各数据集的指定前缀建立候选池，按文本与来源条目去重，再应用长度和类别规则，以种子 `20260602` 每类选择十条。数据集和读取数量见[查询抽样](api_route.md#查询抽样)。`category`、`risk_level` 和 `control_type` 描述研究分组，原始查询及其出处保存在来源字段中。

正式采集前，逐条阅读查询并确认类别。为事实与官方信息对照组记录适用的一手来源；为存在多种解释的查询记录选定的对象、地区和时间范围。将修订后的查询 CSV、抽样清单和原始条目记录一同保存。

## 采集设计

以 `minimal` 为基础条件，使用同一查询集合比较 `primary_aware` 和 `official_diagnostic`。`bare_query` 用于比较查询包装措辞，`research_context` 用于考察加入研究背景后的回答。每个条件都通过搜索工具获取网页来源，具体指令见[提示词配置](api_route.md#prompt-profile)。

为每个条件指定独立采集目录。比较提示条件时固定模型、推理强度、搜索上下文设置和每条查询的重复次数；比较模型时固定查询与提示配置。`run_manifest.json` 记录这些设置，汇总 JSONL 记录每次请求的时间和响应 ID。

重复采集按查询配对。例如，同一条查询在两个提示条件下各运行三次，先汇总该查询在各条件下的来源和引用，再比较条件间的变化。报告同时列出查询数量和每条查询的运行次数。

采集完成后运行输出检查器，查看预期运行、响应状态、引用与来源计数。将查询 CSV、运行清单和代码 commit 一同归档，作为该轮实验的配置记录。

## 页面与引用标注

先阅读 `collections/<run_id>.md` 了解回答，再通过[复核队列](data_format.md#复核队列)查看来源页面的规则片段和引用上下文，使用 `text_path` 打开提取文本。`fetch_manifest.csv` 保存页面获取与提取状态，帮助安排补充核查。

页面标签以 `url_id` 关联，引用标签以 `run_id` 和 `citation_order` 关联。这样可以分别描述页面自身的特征，以及同一页面在各处引用中的作用。

| 标注维度 | 记录内容 |
|---|---|
| 发布者类型 | 政府或公共机构、学术机构、厂商、媒体、服务商、社区等 |
| 页面用途 | 原始文档、研究报告、产品说明、评测排名、聚合摘要、问答、服务推广等 |
| 商业关系 | 联盟链接、赞助披露、佣金、广告和咨询入口 |
| GEO 相关特征 | 面向 AI 搜索的优化表述、指令式内容、权威性包装、时效性包装、选择性呈现 |
| 引用作用 | 支持关键断言、补充背景、提供实例、引出推荐或说明争议 |
| 证据关系 | 充分支持、部分支持、内容矛盾、待核查 |
| 判断依据 | 页面片段、回答上下文、对照资料和标注理由 |

对低原创性、事实表述和权威性包装的判断，保存原始出处或对照资料。标注者依据同一套定义独立阅读，分歧记录原始判断与讨论后的结论。页面内容按本次抓取版本归档，时间敏感的案例在实验记录中补充获取日期和相关版本材料。

复核队列的分数安排阅读顺序。估计整体比例时，标注方案覆盖完整页面清单，或预先按查询类别、引用状态和规则分数组合抽样，并记录各组样本量。

## 暴露分析

分析时分别统计搜索来源暴露和回答引用暴露。搜索来源使用 `sources.csv`，回答引用使用 `citations.csv`，页面标签通过 URL 清单关联。引用事件、响应内唯一页面和查询覆盖的计数示例见[计数与表间关联](data_format.md#计数与表间关联)。

将人工标签与采集记录连接后，可以计算以下指标：

| 指标 | 计算方式 |
|---|---|
| 特征引用占比 | 带有指定页面特征的引用事件数 / 已完成该特征标注的引用事件数 |
| 特征来源占比 | 带有指定页面特征的来源记录数 / 已完成该特征标注的来源记录数 |
| 查询暴露率 | 至少一次引用目标特征页面的查询数 / 完成相应标注的查询数 |
| 来源到引用的转化率 | 同次响应中被引用的目标来源页面数 / 同次响应中返回的目标来源页面数 |
| 重复运行的来源重合度 | 两次响应的引用 URL 集合交集大小 / 并集大小 |

来源到引用的转化率按每次响应中的唯一页面计算，重复引用在这一指标中计为一个页面。来源重合度以两次响应的引用 URL 并集为分母；并集为空的配对单列为“双方均无引用”。

按查询类别和提示条件分别汇总这些指标，并列出样本量、标注覆盖率、页面获取状态和待核查数量。报告原始计数与比例，读者便可沿表间关联回到对应回答和页面。

## 来源替代分析

来源替代分析考察回答为具体断言选择了什么证据，以及一手资料在其中的使用情况。选择价格、规格、规则、步骤或专业建议等可定位断言，为每个案例建立一条对照记录：

| 内容 | 记录方式 |
|---|---|
| 回答断言 | 原文片段、`run_id` 和引用序号 |
| 现有引用 | 页面 URL、发布者、支持该断言的原文 |
| 一手资料 | 原始研究、官方文档、厂商资料或机构说明的 URL 与证据片段 |
| 适用条件 | 对象、地区、时间和问题范围 |
| 比较结论 | 对准确性、完整性、时效性和商业表述的逐项判断 |

例如，回答借助评测文章描述某款产品的接口规格时，可将评测原文与该型号的厂商规格表配对；回答引用服务商解释办理规则时，可与对应机构的办理说明配对。统计这些案例在各类查询和提示条件中的分布，再分析来源选择与回答内容之间的关系。

## 来源干预实验方案

回答影响可以通过可控检索生成系统中的来源干预研究。选取已完成证据配对的案例，准备完整来源、移除目标来源、以一手资料替换目标来源三个条件，并固定查询、生成模型、提示词和其他检索内容。

实验逐次记录输入来源及生成回答，再比较推荐对象与排序、关键事实、风险说明、立场和引用归属。按查询配对分析重复运行，分别记录引用变化、措辞变化和实质建议变化。实验报告列出所用系统、来源条件、运行设置及对应案例。

## 结果组织

研究报告围绕以下材料组织结果：

- 查询与采集设置：查询出处、类别、模型、提示条件、采集时间和重复次数。
- 来源分布：各类别的来源与引用计数、域名分布、页面特征及标注覆盖率。
- 证据案例：回答片段、引用页面、一手资料和比较理由。
- 条件比较：提示条件或来源干预前后的变化，附查询级配对结果。

表格中的每项结果保留实验 ID、查询 ID、运行 ID 或页面 ID，便于从统计结果追溯到采集记录和标注依据。
